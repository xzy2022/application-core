## 增大交换内存
```bash
# 1. (再次确认) 查看当前磁盘空间
df -h /

# 2. 分配一个 16GB 的文件 (在根目录下，这会占用你 Ubuntu 的 16GB 硬盘空间)
sudo fallocate -l 16G /swapfile_extra

# 3. 设置只有 root 读写权限 (为了安全)
sudo chmod 600 /swapfile_extra

# 4. 把这个文件格式化为 Swap 格式
sudo mkswap /swapfile_extra

# 5. 立刻启用它 (救命的一步！)
sudo swapon /swapfile_extra

# 6. 验证是否成功
free -h

# 备份一下配置文件 (好习惯)
sudo cp /etc/fstab /etc/fstab.bak

# 把 swapfile 配置追加到 /etc/fstab 文件末尾
echo '/swapfile_extra none swap sw 0 0' | sudo tee -a /etc/fstab

# 看最后一行是不是多了 /swapfile_extra ...
cat /etc/fstab
```

## 实验流程深入理解
该场景主要负责控制车辆在红绿灯路口的停止和通行。其核心逻辑分为两个阶段（Stage）：

### 场景进入条件 (IsTransferable)
- 车辆处于车道保持（Lane Follow）状态。
- 前方参考线上遇到红绿灯（Signal）。
- 距离红绿灯的距离小于 start_traffic_light_scenario_distance。
- 红绿灯当前状态 不是绿灯（即红灯、黄灯或未知），或者虽然是绿灯但距离很近。

### 接近阶段 (TRAFFIC_LIGHT_PROTECTED_APPROACH):
- 这是场景的初始阶段。
- 红灯/黄灯时：车辆会在停止线前减速并停车。
- 绿灯时：车辆继续行驶接近路口。
- 阶段切换条件：当车辆距离停止线足够近（小于 max_valid_stop_distance）且 信号灯变为 绿灯 时，该阶段结束，切换下一个阶段。

### 路口巡航阶段 (TRAFFIC_LIGHT_PROTECTED_INTERSECTION_CRUISE):
- 当车辆通过了停止线检查（即绿灯且已到达路口），进入此阶段。
- 车辆将穿越路口，完成该场景的任务。

#### 路口巡航阶段的速度计算

- ST_BOUNDS_DECIDER：在 ST 图上投影障碍物、限速、车道边界等，生成路径-时间可行域（初始 S/T 上界/下界），为速度规划提供空间。见 modules/planning/tasks/st_bounds_decider/*.

- SPEED_BOUNDS_PRIORI_DECIDER：在已生成的 ST 可行域基础上，结合限速、曲率、跟车距离，给速度再加一层先验上下界（粗约束）。这会写入 st_graph_data 里的速度上/下界。见 modules/planning/tasks/speed_bounds_decider/*。

- SPEED_HEURISTIC_OPTIMIZER (PathTimeHeuristicOptimizer)：在先验约束的 ST 图上跑一次启发式/贪心或 DP，产出一条可行的速度参考曲线，用于后续决策/优化的引导。见 modules/planning/tasks/path_time_heuristic_optimizer/*.

- SPEED_DECIDER：根据交通规则（停车、让行、跟车等）调整或插入停止点/减速要求，把规则性约束刻到 ST 图或参考曲线上。见 modules/planning/tasks/speed_decider/*.

- SPEED_BOUNDS_FINAL_DECIDER：在经过规则调整后，对 ST 可行域和速度上下界做最终修正（确保规则/障碍/限速都被考虑）。依旧使用 speed_bounds_decider 的逻辑。

- PIECEWISE_JERK_SPEED：最终的速度优化器。以最终 ST 约束、规则约束和参考曲线为输入，求解带加速度/加加速度约束的速度曲线，输出真正用于轨迹拼接的速度剖面。见 piecewise_jerk_speed_optimizer.cc.
